# Changelog

Write the user-facing changes for each release under `## Unreleased` before
running the Desktop Release workflow. The workflow copies that section into
**What's new in this release** and uploads a promoted changelog artifact after
publishing; land that artifact through a normal pull request. A release whose
`## Unreleased` section has no bullet stops before building.

## Unreleased

- **The desktop app no longer takes the `agent-relay` command name.** On Linux and Windows the GTK launcher is now `agent-relay-desktop` (`agent-relay-desktop.exe` on Windows), including app shortcuts, updates, launch at login and the Windows background task. `--headless` and `--install-launcher` keep working under the new name, while `agent-relay` remains available for the command-line tool. Existing Linux tarball and Windows installs need one manual upgrade to this release because their old in-app updater requires the former filename: install the new `.deb` or unpack the new Linux tarball, or run the new Windows Setup program. In-app updates resume afterward. macOS is unaffected.
- **Muse access stays inside sessions Agent Relay starts.** On macOS and Linux, Agent Relay no longer discovers or messages Muse sessions opened in a terminal or hosted by another app. Relay-owned Muse spawns keep their existing sandbox, follow-up messaging and lifecycle behavior; Muse remains unavailable on Windows.
- **Cursor Cloud agents join Agent Relay without the local `cursor-agent` CLI.** Agents can discover models, cached repositories and environments, list existing agents and runs, start one with an idempotency key, inject follow-ups while it works, read or cancel run results, and archive or restore it through the shared core on macOS, Linux and Windows. Agent Relay Cloud keeps the Cursor API key and registers each hosted agent as `cursor-cloud`, so messages become Cursor follow-ups and never expose credentials to the desktop or agent sandbox.
- **Community builds no longer send analytics to Agent Relay's PostHog project.** Official macOS, Linux and Windows releases still support the same opt-out analytics, but their ingestion configuration now comes from protected release secrets instead of the source tree. Forks, local builds and tests contain no project configuration and send nothing.
- **Public examples use generic people and computer names.** Documentation and the trusted-senders placeholder on macOS, Linux and Windows no longer expose names from Agent Relay's internal development environment.
- **The Linux headless installer now downloads from the public releases page.** Install or update the core on a server with `curl -fsSL https://github.com/AgentWorkforce/relay-desktop-releases/releases/latest/download/install.sh | bash`; the old source-repository link no longer works once the source moves.
- **Every download now includes the Apache 2.0 license.** The macOS app, the Linux tarball and `.deb`, the Windows zip and Setup program, and the standalone core archives ship `LICENSE` and the agent icons' license.

## v2026.10.58

- **Failed Claude Code delivery changes keep their error visible.** On macOS, Linux and Windows, refreshing the approval state after a refused change no longer hides why it failed. A later explicit refresh still clears a recovered error.
- **Agent Relay spends less CPU keeping sessions up to date.** On macOS, unchanged updates reuse the session list and its search data, and upload indicators animate without rebuilding the table. On macOS, Linux and Windows, a session-file change scans the affected provider instead of every provider; periodic full scans still discover new roots and recover missed changes.
- **Every switch and button answers at once.** Changing the upload policy, pausing or resuming, retrying or compacting uploads, a core setting's switch, renaming an agent or putting a session on the relay under a name, sending a message (from the composer, under a spawned agent or as an agent's test message), sharing a Codex thread or approving a held message, allowing or restricting Claude Code delivery, releasing a fleet worker, dismissing a seat or revoking a grant, and starting at login on Linux and Windows now show the change the moment you make it, the way the upload and messaging switches already did: the policy row moves and stays usable with a small spinner, the message appears in the conversation as *Sending…*, the released worker reads *Released*, and so on. If Agent Relay cannot make the change, the control goes back to what the core reports and the reason shows beside it; clicking again while a change is still saving makes the last click win. Logging out on macOS now shows *Disconnecting this computer…* until the account is gone, and a second sign-in click while the first is starting does nothing, as on Linux and Windows.
- **A column edge stops being highlighted once you finish resizing.** Dragging the edge of a sessions-table column used to leave that edge highlighted until something else took focus. It now clears as soon as you let go, cancel with Escape or double-click to reset the width. Same on macOS and Linux.
- **Windows: Upload session works while uploads are running.** Since the first Windows release, turning on **Upload session** in an open session, or **Upload** for selected rows, did nothing and showed no error, and the upload status could not be read, whenever the uploader was running: Windows reports a lock another process holds differently from Linux and macOS, and the app took the running uploader's own lock for a failure. The switch now uploads the session and the Upload column reports its progress, as on Linux and macOS. Nothing changes on macOS or Linux.

- **Relay core failures leave a local diagnostic log.** On macOS, Connect failures and other core diagnostics are saved in `~/Library/Logs/Agent Relay/core.log`, even when the background service has no terminal. Agent Relay Dev uses its own log folder. Linux and Windows keep the same log in the app data directory's `logs` folder; Linux also keeps its systemd journal output. Logs redact credentials and rotate automatically at 1 MiB, keeping three backups.

## v2026.10.57

## v2026.10.53

- **Edit session titles without leaving Agent Relay.** On macOS and Linux, hover a title and click its pencil to edit it. The sparkle button fills in the pipeline’s saved title, preloaded when available; Enter saves and Escape cancels. Titles update immediately and roll back with an error if the original harness cannot save them. Unsupported sessions explain why editing is unavailable.

Capability checks explain unavailable routes; a rename never sends an agent prompt or changes the Relay agent’s address.

- **Spawns no longer fail when Agent Relay is slow to register the agent.** When Agent Relay Cloud was under load, it could take longer than 10 seconds to register a spawned agent, and the spawn failed with "Agent Relay did not register the agent in time" even though the agent had been registered. The computer now waits up to 30 seconds more for that answer and launches the agent when it arrives. On macOS and Linux.
- **Relay Connect retries overloaded sends without duplicating them.** Every Connect message now carries a fresh idempotency key, so Relay can retry a temporary server failure and still accept it only once. If the final outcome is unknown, the socket error returns the key to use for an exact retry.
- **Pi messages keep their order and channel answers return.** On macOS and Linux, messages queued while Pi is busy now run in arrival order, and an answer to subscribed channel posts returns to the last post automatically. Retries retain that original reply target even if a post leaves the queue. Extension installation failures stay visible in the app's status and Settings instead of leaving an empty session list without an explanation. Run `/reload` in Pi to load the updated extension, then turn its Relay registration off and on again.
- **Relay agent names describe their work.** New automatic names use the harness, repository, and up to two meaningful words from the session title, such as `claude-cloud-plan-support`, instead of a random-looking suffix. Duplicate names get a number; sessions without a task title use `session`. Existing and explicitly chosen names stay unchanged. Shared by macOS, Linux and headless mode.
- **Start Replicas agents through Agent Relay Cloud.** Once an owner connects Replicas in Cloud, agents can discover environments, start a replica, check its Relay connection, and release it through the shared core on macOS and Linux. Cloud owns delivery and credentials; it does not need a bridge running on your computer.
- **Antigravity and Oh My Pi sessions are tracked and uploaded.** RelayHistory 0.49.0 also reads Antigravity's App, CLI and IDE transcripts and Oh My Pi's sessions, like Claude Code, Codex and Pi ones, subject to your session-sharing setting. Oh My Pi sessions kept beside Pi's are not listed twice. On macOS and Linux.
- **OpenClaw no longer lists a session for every heartbeat.** Each OpenClaw heartbeat or cron run used to show up as its own session, so a single cron job could fill the list with dozens of near-empty rows. Agent Relay now uses RelayHistory 0.49.0, which shows each OpenClaw conversation once, as OpenClaw's own session list does: every run of a cron job, and every reset of a chat, is part of one session, and heartbeat check-ins are no longer counted as your prompts. OpenClaw sessions already uploaded are re-listed under their conversation the next time history syncs, and the old per-run copies are removed from the cloud. Your choices carry over to the conversation. If you deleted any of its runs from the cloud, it is not uploaded. If you excluded any of its runs, it is not uploaded either, unless you share “Only sessions I choose” and chose another of its runs. On macOS and Linux.

## v2026.10.51

- **The menu-bar panel and Linux tray are an at-a-glance summary.** Instead of a list of recent sessions, the menu shows how many of this computer's agents are **Receiving messages** and how many are **Local only**, and how many sessions are **Uploaded** and **Not uploaded**; each count opens its page in the app. On the Mac the counts are badges, blue while live and muted otherwise, and the upload status is a dot beside Sessions that says what it means on hover. **Open Agent Relay**, **Settings…** and **Quit Agent Relay** sit at the bottom.
- **Uploads and messages use your Agent Relay account's workspace, and only that.** Agent Relay no longer reads a workspace key from `RELAY_WORKSPACE_KEY`, `RELAY_API_KEY`, the `agent-relay` CLI's files or a key pasted into the app, so a stale or over-quota key elsewhere on the computer can't send your agents to another workspace. Settings › Messages shows **Workspace from your Agent Relay account**; switch workspaces from the account menu. The paste-a-key sheet and the workspace-mismatch notice are gone on macOS and Linux. A key you pasted before is dropped; agents registered in another workspace stay there until you turn them off and on again.
- **Agent Relay starts its background service again on Macs where macOS lost track of it.** On some Macs, macOS reported the service enabled while it could not find the helper inside the app and kept failing to start it, so the app waited on the core forever. Agent Relay now detects that and registers the service by its full path instead, asking for Login Items approval if macOS needs it. The app must run from **Applications** (or `~/Applications`); opened from the disk image or another copy, it says to move it there first.
- **Agent Relay warns when a Claude Code session stops reading its messages.** Claude Code reads messages delivered to a terminal session only when its current turn ends, so a session whose turn is stuck kept collecting messages while it still looked active. Agent Relay now watches the session's transcript, and when a delivered message has sat unread with no progress for 10 minutes it adds a warning to Activity and marks the agent stalled (with how many messages wait and for how long) in the core's `agents.list` and in `GET /agents` on the session socket. The warning clears once the session reads them. Set `RELAY_DESKTOP_CLAUDE_INBOX_STALL_SECS` to change the 10 minutes. Delivery itself is unchanged: messages are never resent.

## v2026.10.50

- **Give your OpenClaw agents Agent Relay's tools in one click.** While OpenClaw is on, Settings → **Agent Relay tools** has **Connect**: Agent Relay adds its hosted MCP to `openclaw.json` (or reuses one already there) and opens its consent page in your browser, where you pick a workspace and agent name and click Approve, as for Grok Bot and ChatGPT. Your OpenClaw agents can then list agents on the relay, message them and spawn new ones, with no terminal or config editing. Messages from people who aren't trusted senders still never get these tools. On macOS and Linux.
- **Session uploads no longer stop while macOS waits to allow access to Claude Code's sign-in.** On a Mac where Claude Code keeps its claude.ai sign-in in the Keychain, the sessions helper waited for the answer to macOS's "allow access" prompt before doing anything else, so when nobody answered it (a headless Mac, or nobody at the screen) the collector stayed on **Scanning catalog…** and no session was uploaded, for hours. The helper now waits a few seconds at most: until the prompt is answered, Claude Code cloud sessions are skipped ("Waiting for Keychain access to Claude Code's sign-in") and every other session uploads as usual, without a second prompt. Once you allow access, cloud sessions are picked up on the next pass; if you deny it, the helper does not ask again for an hour.
- **OpenClaw no longer needs upgrading to join the relay.** Agent Relay now works with every OpenClaw from 2026.3.13 on, choosing what it sends from what the Gateway reports, so an older Gateway no longer refuses the connection or a message. Every sender still gets a session of its own, and an agent's answer still goes back to that sender only, with no duplicate turns. OpenClaw older than 2026.8.1 cannot limit relay sessions, so on those versions anyone on the relay who messages your agents gets a session with the agent's usual tools; Settings → **OpenClaw agents** says so on macOS and Linux, and updating OpenClaw to 2026.8.1 or later makes those sessions answer-only.
- **A relay message is no longer sent to OpenClaw twice.** On every released OpenClaw up to 2026.10.4, Agent Relay's check of a sender's OpenClaw session was refused, so a retried delivery could start a second turn and a new message could land while the agent was still answering the previous one. The check now asks only for what every OpenClaw accepts.
- **OpenClaw sessions are tracked and uploaded.** Agent Relay now uses RelayHistory 0.47.0, which reads every OpenClaw agent's sessions (main, Telegram, relay, cron and subagent chats) like Claude Code, Codex and Hermes ones, subject to your session-sharing setting. It works on every OpenClaw from 2026.3, including the JSONL session store that versions before 2026.8.1 use, and a session OpenClaw later imports into its database is not uploaded twice.
- **Agent Relay no longer offers a Claude Desktop handoff that Claude Code will refuse.** **Open in Claude** ran `claude --desktop --resume`, which Claude Code refuses for a session another process is already running ("Session … is open in another terminal. Run /desktop there instead.") — and the sessions at the top of the list are running ones, so it failed nearly every time it was clicked. Agent Relay now reads what holds each Claude Code session and offers only what works: a session you are typing in keeps **Open in Terminal**, with a note to run `/desktop` in that terminal to continue it in Claude; a session a headless process holds has no open action, with a note to run `claude agents` to find it. **Open in Claude** comes back once nothing holds the session. On Linux, where Claude Code has no desktop handoff, the headless session is the one that changes.

## v2026.10.48

- **A renamed agent's previous name keeps working for a day.** When a session is renamed again, the name it replaces is hidden from rosters and never used to send, but still forwards messages to the session for 24 hours, so a late reply arrives. Renaming back to it within that time takes it up again, and every name is released when the agent leaves the relay. The name the session was registered with still forwards for as long as it is on the relay. The rename message on macOS and Linux says so.
- **Agent Relay no longer floods Relaycast when more than 20 sessions are waiting to join.** v2026.10.47 rewrote every agent's Relaycast metadata about every 45 seconds once more sessions were held back by auto-activation than its journal keeps, which could use up a workspace's plan and bring back **Agent Relay plan limit reached**. The journal now stays the same while the same sessions are blocked, and is republished only when which sessions are blocked, or why, changes. On macOS and Linux the plan-limit and capacity notices also ignore a limit hit in a Relay Connect room, which is that room's own workspace.
- **Cloud identity sync no longer retries an unchanged refusal every minute.** Native spawned agents stay under their audited Cloud spawn identity instead of being submitted as desktop sessions, and another permanent identity refusal is reported once; a new sign-in or changed account or identity set retries immediately. The macOS and Linux status bars now say “Agents couldn't link to Cloud” instead of the generic “Cloud request failed.”

## v2026.10.47

- **Agent Relay eases off when Relaycast's database is overloaded.** A `503 database_overloaded` answer now pauses that workspace's background heartbeats, settlements and queue reads for the Retry-After it names, backing off further while it continues, instead of trying the next agent 100 ms later. On Agent Relay's hosted service, agents with a live push connection also send their presence heartbeat every 2 minutes instead of every 30 seconds; they still show as active.

## v2026.10.46

- **Grok Bot sessions open again.** Agent Relay now uses RelayHistory 0.45.2, so opening a Grok Bot session no longer fails with "Probe could not finish" when the app records an entry, role or roster shape RelayHistory does not map; those entries are skipped or kept as context and the rest of the transcript shows.

## v2026.10.45

- **New agents can join #general.** **Settings › Relay › New agents join #general** (macOS and Linux) puts each agent registered from then on in #general, so its posts reach the agent as turns. It is off by default, which keeps agents reached by direct message; agents already on the relay keep the channels they are in.
- **Agents can read and change Agent Relay's settings.** From inside a session, `GET /settings` on the session socket lists every setting the app's Settings shows (its type, value and what it does), and `PATCH /settings` changes them; `agent-relay-probe relay settings` does the same. Every change an agent makes is recorded with its name, the time and the value before and after, listed under **Settings › Relay › Changed by agents**, and written to the activity log.
- **A headless Linux core links its agents to Agent Relay Cloud on its own.** A computer attached by setup, without signing in through the app, never saved its workspace binding, so its agents never reached Cloud and a hosted Agent Relay MCP's `join_relay` could not link them ("That desktop identity is not synced…"). The core now binds the workspace itself with the Cloud session the computer already has. This app's own kept session is renewed for it when needed; the Agent Relay CLI's sign-in is only read, never renewed or rewritten, and an expired one gets "sign in again" guidance. A session borrowed from the environment or the CLI is used only once Agent Relay Cloud confirms it belongs to the person this computer is signed in as, so another person's sign-in never carries this computer's agents. `GET /setup/status` reports `cloud_identity_sync` (`ready`, `sync_failed`, `no_binding`, `no_session`, `cli_session_expired` or `session_mismatch`), and the service log says when agents cannot reach Cloud and how to fix it.
- **Choose who may spawn agents on this computer.** Agent Relay now claims this computer's spawn node for you in Agent Relay Cloud, so agents can pick it as a place to spawn. **Settings › Spawned agents** shows whether the claim went through, with **Retry** if it failed, and adds **Allow teammates to spawn here** (off by default: only you can start agents here; on: workspace owners and admins can too). A computer whose node another account already claimed takes no spawns and says so.
- **Spawned agents survive more failures.** A spawn whose registration answer was lost is found again by its invocation and settled instead of left behind, and a node's spawn results are sent again after a restart until Relaycast takes them. A spawn still reserved after a restart holds one place, not two, and a Grok launch whose leader disappears fails instead of hanging.
- **Taking over a spawned agent on Linux stays with that agent.** **Interrupt Now** and any take-over error stay with the session that started the take-over, even after you switch to another transcript.
- **Relay messages are not repeated after a refused Codex turn.** When Codex refuses a turn for channel posts it already holds, Agent Relay waits instead of delivering them again; a Grok agent keeps its slot when its process can't be looked up.
- **The Linux installer keeps a core it can roll back to.** Moving from the in-app updater's layout keeps that core under `versions/`, so `install.sh --rollback` can return to it.
- **The relay messages setting says what it changes.** **Show relay messages in agent chats** is now **Show me relay messages in full**: it only changes what you see. The agent gets every relay message in full either way.

## v2026.10.44
