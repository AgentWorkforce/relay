# Moving the probe core into relay

The Agent Relay desktop "probe" is the native Rust core that discovers
running coding-agent sessions and injects Relay messages into them through
each harness's native route (Claude Code, Codex, Devin, OpenCode, Grok, Pi,
Cursor CLI, OpenClaw, Hermes, Muse). It lived in relay-desktop next to the
apps. This note covers moving **only the core** into relay as `crates/probe`,
so the relay CLI can install and run it headless and injection works without
the desktop GUI. relay 15.0.0 is held until injection works through the probe.

## Decisions

- Only the core moves. The macOS, GTK (Linux and Windows) and iPad apps stay
  in relay-desktop and consume the core from relay.
- **Clean snapshot, no history.** relay is public, and relay-desktop's history
  holds documents and a PostHog key that were later scrubbed. Phase 1 imports
  the tree at relay-desktop `origin/main` as new files only.
- **Own Cargo workspace.** `crates/probe` has its own `[workspace]` and
  `Cargo.lock`. It does not join the root (broker) workspace yet, because the
  two pin conflicting `relaycast` (10 vs 9), `nix` (=0.25.1 vs 0.30) and
  `portable-pty` (=0.8.1 vs 0.8) versions.

## What stayed in relay-desktop

- **The GTK app**: `probe/src/linux_app/` (about 41k lines: `bridge`,
  `fake_core`, `host`, `launch`, `models`, `prefs`, `service`, `ui`,
  `updates`), the `gtk` feature, the `agent-relay` (GUI launcher) and
  `agent-relay-fake-core` binaries, and the tests `linux_app_gtk` (and
  `tests/linux_app_gtk/`), `linux_app_hosting`, `linux_app_core_e2e` and
  `linux_package`.
- **GUI-only dependencies** removed from the core's manifest: `gtk4`, `ksni`,
  `tray-icon`, `tauri-winrt-notification`, `zip` and `tar`. Removing them
  pruned 107 packages from `Cargo.lock`. No other package was added or
  upgraded.
- **GUI assets**: `probe/resources/linux/` and `probe/resources/windows/`.
- **Everything outside `probe/`**: `macos/`, `ipad/`, `shared/` (including the
  `RelaySessionOverview` Swift package, which keeps its own copy of the test
  vectors), `linux/` and `windows/` packaging, `scripts/`, the CalVer
  `CHANGELOG.md`, `assets/`, `integrations/`, the remaining `docs/`, and the
  workflows.

## The GTK split

Only three places in the core referenced GUI code, and none of them needed GTK:

| Core file                     | Used                                                                                                                                                    | Resolution                                                                   |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `src/relay/login_item.rs`     | `linux_app::install` (`probe_tree`, `APP`, and on Windows `install::windows::{command_program, registry}`) to find the packaged app for launch at login | Moved `install` (and `install/windows.rs`) into the core as `crate::install` |
| `src/relay/session_query.rs`  | `linux_app::models::{LocalSessionQuery, LocalSessionRow, StatusView, SessionUploadState}` for the core's session catalog query                          | Moved the closure of those types into the core as `crate::session_model`     |
| `src/relay/uploader/query.rs` | `linux_app::models::StatusView`                                                                                                                         | Same as above                                                                |

`crate::session_model` holds the six modules that closure needs, unchanged
apart from paths: `agent_kind`, `agent_names`, `local_sessions`,
`session_project`, `session_query` and `uploads` (with `uploads/`). It also
holds the four helpers they call from `models.rs` (`grouped`, `capitalized`,
`sessions_noun`, `search_matches`) and a private copy of `settings::origin`,
so the 944-line `settings` module did not have to move. Their unit tests moved
with them. The `include_str!` paths now point at
`tests/fixtures/shared/`.

No core test depended on GTK. The excluded tests are all tests of the app.
`linux_app_core_e2e` does drive a real core, but through the app's bridge
client (`linux_app::bridge`), so it stays with that client.

## Version stamping

`build.rs` no longer reads relay-desktop's `CHANGELOG.md`:

- `AGENT_RELAY_PROBE_VERSION=X` stamps exactly `X`. Releases already pass
  this. relay-desktop's `build-probe.sh`, `build-linux.sh`,
  `build-windows.sh` and `desktop-release.yml` pass the desktop CalVer, and
  a relay release would pass the relay version.
- Otherwise, a development build is `<base>-dev+<git revision>`. The base is
  `AGENT_RELAY_PROBE_BASE_VERSION` when set: relay-desktop should pass its
  newest CalVer, which it used to read from its changelog, so development
  cores still order below the next desktop release. Without it, the base is
  the crate version (`0.1.0`).

## CI

`.github/workflows/probe-ci.yml` runs only for `crates/probe/**` (and its own
file). It runs:

- a Linux x64 build and test, with an empty `HOME`;
- a macOS arm64 build and test;
- a Windows x64 build (MSVC);
- the contract-drift check (`generate-contract.sh`, then `git diff
--exit-code`);
- the public-source check.

PR runs cancel superseded runs, and other runs get per-SHA groups (the
relay#2010 pattern). Actions are pinned to the SHAs relay already uses.

relay-desktop CI checks that are not ported yet:

- `rust-oleum` (the config moved and was pruned of GUI entries);
- the glibc 2.34 floor;
- arm64 Linux, x64 macOS and arm64 Windows lanes;
- the Pi live-session scripts.

## Phase 1.5: the core without relayhistory

relay must not depend on relayhistory, and relay and relay-desktop must be
able to share one core. Session history, meaning local capture and upload to
RelayHistory, is the only part of the crate built on `ai-hist`. It is now
behind a `history` Cargo feature, on by default:

- **relay** builds `--no-default-features --features production-binaries`.
  That build has no `ai-hist` or `history-provider-sources` in its
  dependency tree, and CI checks this.
- **relay-desktop** builds with the defaults and gets everything it has
  today.

The coupling was narrow: about a dozen of the 474 files under `src/relay/`.
Behind the feature are:

| Gated | What it is |
|---|---|
| `delivery`, `destination`, `retention` | The upload queue, the RelayHistory receiver and history retention |
| `relay::session_query` (and the uploader's catalog search) | `sessions.query`/`sessions.facets` over `history.db` |
| The uploader's background monitor and history reader | Reads `history.db` directly |
| `relay::history_retention`'s store | Saves the retention policy in RelayHistory's store |
| `relay::devin_cloud`, `relay::claude_web` catalog reads and Devin Cloud send | The remote sessions come from the history catalog and `history-provider-sources` connectors |
| Hermes title roots (`session_titles::extra`) | `ai-hist`'s provider-root resolver |
| `cloud::devin_credential` and the auth-refresh send path | Used only by uploads and the Devin connector |
| The binary's history commands (`cloud`, `run`, `start`, `status`, `sessions`, `sharing`, `history flush`, …) | The collector |
| 9 integration tests and the `native_visibility_host` example | History tests (`required-features = ["history"]`) |

Things that stay in the core:

- The pure delivery stall rules moved to an ungated `delivery_status`
  module.
- The binary's JSON output helpers moved to `src/probe/output.rs`.
- `HISTORY_VERSION` is history-only. `history_version()` returns `None`
  without the feature.

The bridge contract is identical in both builds, so the apps need no change.
Without history, the history-backed methods either refuse (catalog search)
or answer empty, as the crate README describes.

This is the first step of the split. It is a feature, not yet two crates,
so it stays reviewable. The next step moves the gated code into its own
crate (for example `agent-relay-history`, depending on the core and
`ai-hist`), hooked into the core through traits in place of the `cfg`
seams above. relay-desktop would then depend on both crates. The `cfg`
seams mark exactly where those traits go:

- session catalog search;
- history retention;
- the remote-session source and sender (Devin Cloud, claude.ai);
- the uploader's history reader.

## Remaining phases

2. **The probe reads the CLI's workspace.** Today `src/relay/workspace.rs`
   resolves the Relaycast workspace only from the Cloud sign-in (`cloud` in
   the agent store, optionally re-originated by `RELAYCAST_URL`). It must
   follow the CLI's ladder (`packages/cloud/src/project-workspace-key.ts`):
   1. the env key;
   2. the project pin `<project>/.agentworkforce/relay/workspace-key.json`;
   3. the machine-global active entry in
      `$AGENT_RELAY_HOME|~/.agentworkforce/relay/workspaces.json`.

   It must honour `relaycast-origins.json` origin bindings, so that
   self-hosted keys never go to the hosted gateway. Then local and self-hosted
   setups work without a Cloud sign-in. The core already locates the CLI's
   home (`workspace::relay_home`) but only reads it.

3. **`relay init` installs and runs the probe.** It downloads
   `agent-relay-probe` into `~/.agentworkforce/relay/bin`, runs `relay serve
--headless` as a per-user service, and installs the probe's delivery hooks
   through its `harness_setup` (Claude Code SessionStart and Stop hooks, the
   Codex app-server, the OpenCode and Pi plugins, and so on). This replaces
   today's MCP-only setup.
4. **relay-desktop consumes the core from relay releases**, one core per
   machine. Whichever of the relay CLI or a desktop app installed the core,
   the other attaches to the running daemon (`~/.agentworkforce/desktop/core.sock`)
   instead of starting a second one.
5. **Real end-to-end proof.** A Codex DM is injected into a running Claude
   Code session without polling, for local, hosted and self-hosted
   workspaces.

## What relay-desktop must change to consume the core

Phase 1 changes nothing in relay-desktop. To switch over, relay-desktop must
do the following:

1. Make the GTK app its own crate (for example `gtk-app/`) depending on
   `agent-relay-probe` from relay (a git dependency on
   `AgentWorkforce/relay` pinned to a tag or commit, `default-features =
false`). That crate takes `linux_app/`, the `agent-relay` and
   `agent-relay-fake-core` binaries, the four app tests, `resources/linux`,
   `resources/windows`, and the dependencies `gtk4`, `ksni`, `tray-icon`,
   `tauri-winrt-notification`, `zip` and `tar`.
2. In `linux_app.rs`, replace `mod install` with `pub use
agent_relay_probe::install;`. In `linux_app/models.rs`, delete the six
   moved modules and `pub use agent_relay_probe::session_model::*;` (keep
   `settings::origin`, which other models still use).
3. Delete `probe/src` (everything but the app) and build `agent-relay-probe`
   from relay's `crates/probe`. That is `scripts/build-probe.sh`,
   `build-linux.sh`, `build-windows.sh`, `package-{linux,macos}-probe.sh`
   and the Desktop Release workflow. Keep passing `AGENT_RELAY_PROBE_VERSION`
   and add `AGENT_RELAY_PROBE_BASE_VERSION` for development builds.
4. Get `CoreContract.swift` either by copying relay's
   `crates/probe/contract/CoreContract.swift` or by running
   `crates/probe/scripts/generate-contract.sh --app-root <relay-desktop>`.
   The generated header now names relay's script. The contract drift check
   becomes "the macOS copy equals the pinned relay core's".
5. Make the core's `shared/session-*.json` vectors canonical in relay, and
   have the Swift tests read relay's copy or sync from it.
6. In CI, drop the lanes now covered by relay's `probe-ci.yml` (Probe,
   linux-core, macos-core-tests). Keep the GTK, Swift, packaging and glibc
   lanes. Repoint `check-open-source.sh`'s license check (`probe/Cargo.toml`)
   at the app crate, and split `rust-oleum.toml` (the GUI entries move with
   the app).
7. Replace relay-desktop's `docs/relay-core.md` and
   `docs/agent-relay-probe.md` with pointers to `crates/probe/docs/`. The
   core's contract test now checks relay's copy.
