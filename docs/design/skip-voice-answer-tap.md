# Skip voice answer tap (held integration seam)

The Codex command watcher already subscribes to loaded threads. This change adds a bounded advisory tap on that connection. It does **not** send text to Cloud or the Mac and is not a live voice stream.

## What the tap accepts

`watch::arm_answer(thread_id, turn_id, relay_message_id, voice_request_id)` is an internal seam. A future caller may invoke it only after Cloud has verified a caller-scoped voice intent for the exact Skip session and `turn/start` has confirmed `clientUserMessageId = relay_message_id` and returned `turn_id`. The two IDs remain distinct: the Relay message is the durable DM; the voice request groups stream events and reconnects. A raw DM `data.voice` field or text marker is not authority.

The watcher then observes `item/started` and `item/agentMessage/delta` on that exact `(thread_id, turn_id)`. It accepts deltas only from items whose type is `agentMessage` and whose explicit phase is `partial_answer` or `final_answer`. It drops commentary and unknown phases, reasoning, tools, plan, other threads, other turns and deltas without an item start. Each accepted delta gets a monotone sequence within that request. Capture retains at most 64 started answer-item IDs per turn; an overflow ends that advisory stream. The backlog is bounded to 512 deltas, 4096 UTF-16 units and 4096 UTF-8 bytes per delta (split at Unicode scalar boundaries), and 64 KiB per answer; overflow stops that advisory stream. Turn completion, thread idle/unload/closure and watcher disconnect end capture. A disconnect also discards buffered text because a gap cannot be replayed safely.

`watch::take_answer` drains only an exact four-ID match. It is internal and does not authorize a person. The future ingress must independently recheck current person, workspace and Skip-session access before every connect or reconnect, and must handle revocation, cursor replay, queue overflow and watcher loss. The durable final Relay DM remains the complete answer and reconciliation source. If the advisory stream is incomplete, the client should wait for that DM.

## Integration still needed

1. Cloud: finish the caller-scoped, signed voice-intent contract and the person-facing stream route. Validate revocation on reconnect and while connected. Carry request ID and Relay message ID on every event. The held offline candidate needs a forgery fix before consumption.
2. Relay core: have the verified delivery path capture the exact returned turn ID and arm the tap. For native continuation (`thread-follower-start-turn`), prove that the watcher observes the same turn or add a separate trusted event tap. The current `start_turn` returns only a boolean; this PR does not change its delivery semantics or attempt to arm from unverified metadata. Connect a bounded core-to-Cloud ingress and define replay/error behavior; `take_answer` drains, so a publisher must buffer acknowledged sequence for reconnect and signal watcher gaps/overflow as fallback rather than silently skipping. On an ambiguous `turn/start`, do not guess the turn or stream another turn's text.
3. Skip: the lead currently sends many replies via `agent-relay-probe send` as a command. Command output is deliberately excluded here. Its user-facing spoken answer must become an `agentMessage` in an answer phase, while the durable DM is sent once. That prompt change and host rollout are separate.
4. Mac: consume only events matching the pinned request, reconcile by ordered sequence, and use the durable DM on a gap or mismatch. Verify in an installed call that the request, turn, audible speech and in-call visual all match.
5. Measure host arrival, queue admission, first answer delta, first audible speech and final DM separately. This tap does not address busy-thread queue delay; see Relay #2298. Per-turn fast settings are Relay #2297.

The local Codex app-server schema used for the filter declares `item/agentMessage/delta` with `threadId`, `turnId`, `itemId` and `delta`, and declares `agentMessage.phase` on `item/started`. It also declares `turn/completed` with `turn.id`. The tap's focused tests cover these shapes and its fail-closed behavior. An installed-host protocol check is required before activation.
